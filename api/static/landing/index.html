01 >

Kliens-oldali tracker.js minden user interakciót (page_view, cta_click, form_submit) strukturált event objektumba csomagol és POST-tolja a collector API-nak.

02 >

FastAPI collector endpoint szigorúan validálja, consent alapján szűri, és idempotensen tárolja a raw_events táblában (ON CONFLICT DO NOTHING).

03 >

Python worker folyamatosan dolgozza fel az új sorokat: dedup, source/medium enrichment, form_submit → leads routing. Hibás rekordokhoz processing_error mező.

04 >

Dashboard REST endpointokról olvassa az aggregált adatokat: pipeline health, conversion funnel, daily time-series, UTM breakdown leads számmal.

ecommerce_mode

// ezen a demón kikapcsolva

Az ECOMMERCE_ENABLED kapcsolóval a collector webshop-eventeket is fogad. Ez a demó lead-gen oldalt mér, ezért itt a kapcsoló ki van kapcsolva, és a dashboard vásárlási adatot nem mutat.

+

Négy további event: view_item, add_to_cart, begin_checkout, purchase. Egy kérésben akár 1000 is beküldhető.

+

Ellenőrzött vásárlás: a purchase eventből csak akkor lesz orders sor, ha van benne rendelésazonosító, pozitív érték, pénznem és vásárlóazonosító.

+

Eszköz-összekapcsolás: vásárlás után az eszköz korábbi eventjei is a vásárlóhoz tartoznak.

+

Kötegelt worker: 5000 sor egy tranzakcióban; ha a köteg elbukik, soronként dolgozza fel újra.

> helyben kipróbálható: leírás a README-ben.

A döntésedet, egy véletlen látogatói azonosítót (localStorage) és egy munkamenet-azonosítót (sessionStorage). Cookie-t az oldal nem használ.
